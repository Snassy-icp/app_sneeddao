# Product pipeline (notes)

Ideas agreed in direction but not started, with where they are specced. Newest last.

| Item | What | Spec / notes |
|---|---|---|
| DAO settings | One generic nervous system function per DAO canister (`dao_set` / `validate_dao_set` / `dao_settings`, shared src/DaoSettings.mo) lets SNS proposals change each canister's fees, prices and limits within bounds in code; propose form in Sneed Hub later. Pilot in Sneedex built and tested (2026-10-23); GNSF 6100 not registered yet. Replaces the sneed proxy for settings (proxy parked: built, tested, kept for multi-step atomic changes). | spec/dao_settings.md (spec/sneed_proxy.md parked) |
| Special prices | Admin and partner prices in every charging canister. Built, on staging; production proposals pending. | spec/special_prices.md |
| Wallet subaccounts | Hold, send, receive and approve from subaccounts in the Sneed Hub wallet. | spec/programmable_accounts.md (phase 1) |
| sneed_vault | Owned subaccount namespaces with per-subaccount funding rules (who may request how much, where, when). | spec/programmable_accounts.md |
| Sneed Monitor funding trees | Monitor any account or canister and top it up, in trees (A tops up B tops up C). | spec/programmable_accounts.md, spec/sneed_mon.md |
| sneed_mon_bot | User-owned automation bot inside Sneed Monitor: triggers, actions, dataflow; gas = its own cycles. | spec/sneed_mon_bot.md |
| Managed bots | For users who don't care about custody: Sneed as shared or sole custodian of their Sneedapp bots, keeping them topped up and upgraded along published versions. Custodian = sneed_guardian with a Sneedapp-bot child kind. Only auto-upgrades need custody; fuel doesn't: cycles top-ups are permissionless (anyone can top up through the CMC), so keeping any bot fuelled works for every bot whose cycles balance can be read, custody or not (via a public cycles query on the bot; check every bot has one). | spec/sneed_mon_bot.md §17, spec/custody.md |
| Notification bot | A user-owned notification canister for heavy users (own caps, own cycles); the shared Sneed Notifications stays the default. | not specced |
| SNS staking bot | Like the ICP staking bot (icp_neuron_manager), but holding SNS neurons: stake, dissolve, follow, vote, disburse maturity, make proposals. Why: SNS neurons are already liquid (transferable, tradable on Sneedex), so the point here is the automation a bot gives (chores, events, botkeys), not liquidity. The ICP staking bot came first because it adds liquid staking to ICP: the bot holding the ICP neuron can be traded on Sneedex even though the neuron itself can't. | not specced; see spec/icp_neuron_manager.md for the ICP one |
| sneed_agent (AI bot) | A user-owned bot that runs AI agents with control over the user's other bots: it can send proposals (through bots that hold neurons), move funds within the budgets and rules it is given (sneed_vault grants, bot botkeys), and drive sneed_mon_bot workflows. Builds on what the bots already have: botkeys (fine-grained permissions per principal, so the agent gets exactly the rights its owner grants on each bot) and the bot event system (the agent reacts to the bots' events). Uses the Sneed Hub MCP tools and the same preview/confirm, caps and audit safety model. Where the model runs (on-chain inference vs. an off-chain worker the bot authorises) is the first design question. | not specced; see mcp/sneed-hub, spec/self-writing-dao/ for Mr Sneed's own design |
| TACO exchange in Sneed Hub swap | Kong is defunct (Swaprunner died with it): add TACO DAO's exchange as a venue in Sneed Hub's swap / split-swap next to ICPSwap. | spec/swap_spec.md, spec/split_swap.md |
| Sandwich-proof swaps (ICRC standard?) | An ICRC-2 approval lands on-chain before the swap call, so a fast bot can see the intent and sandwich the trade (ICPSwap never quite closed this). With owned subaccounts that have hotkey-like rules (sneed_vault, or the DEX itself holding per-user subaccounts the user pre-funds), the DEX may take funds for a swap the user signs, in the same call, with no precursor transaction that reveals the trade. The user began this design for Swaprunner a year ago. Worth proposing as an ICRC standard ("subaccount grants"). | spec/programmable_accounts.md; earlier Swaprunner work (swaprunner_backend in dfx.json) |
| sneed_notes (soon) | Sneed's own Twitter: users write their own posts outside the forum and subscribe to each other. A personal feed under the /me pages shows what you subscribe to: people's notes, and also anything from the general feed (forum topics/threads, Sneedex auctions, a whole DAO's activity, etc.). Ties in with Sneed Notifications (notify on new notes from people you follow) and the naming/profiles/avatars canisters. Scaling: like the bots, a user can get their OWN notes canister (minted via Sneedapp, their cycles, their limits, managed/topped up like other bots); the shared notes canister serves everyone else, and the feed reads from both (a registry of who publishes where). See the SMS/forum scaling notes. | not specced |
| Sneed stake gate | DAO-owned canister reporting a principal's SNS/NNS stake (cached queries + refresh), so on-chain dapps can gate content, rooms, items or memberships on stake (off-chain services query SNS governance directly); rules stay in each dapp. | spec/sneed_stake_gate.md |
| Sneed SDK | `@sneeddao/sdk`: JavaScript SDK for integrators (Sneed Lock first, then Notifications, Sneedex) and the shared core of Sneed Hub, the MCP server and the support tools (ids, derivations, safe transfers, ICRC-3, typed actors from the release .did). `sdk/` workspace, MIT GitHub mirror for installs, npm and mops later. | spec/sneed_sdk.md |
